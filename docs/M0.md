# M0 answers

The spike ran on Hyprland 0.57.0, one 1920×1080 monitor at 1×, Rune at `781e2b6`, release build.
The two Rune fixes it needed are recorded in `docs/RUNE-PATCH.md`.

| Question | Answer | Evidence |
|---|---|---|
| Does `OnDemand` + `request_keys()` give key focus at once on a fullscreen surface, with no click? | **Yes, with the Rune keymap fix.** Hyprland's keymap fd was at EOF; after reading it at offset 0 with `pread`, a synthetic Escape reaches the overlay immediately. | `hyprctl layers` shows the `dusk` layer; `wl_keyboard.enter` arrives before the first key; Escape closes the menu. |
| Can a windowless app run only overlays and quit cleanly? | **Yes.** `App::windowless()` + one overlay per display; `AppHandle::quit` removes the surfaces and the process exits. | process exits; `hyprctl layers` no longer lists `dusk`; no `dusk` process remains. |
| Does each display get its own overlay, with the right monitor targeted? | **Implemented, one monitor verified.** The factory gets every `Display`, targets `DisplayId`, and the menu goes to the Hyprland focused monitor by name. Two-monitor mixed-scale testing remains in the release matrix. | one monitor: overlay created at its output; focused name matched through `j/monitors`. |
| Does the overlay's name become the layer namespace, and does the blur rule apply? | **Namespace yes; blur is compositor policy.** `hyprctl layers` lists `namespace: dusk`; Sway has no layer blur, Niri uses a `layer-rule`, and without either dusk thickens its veil. | `hyprctl layers`; `dusk doctor`. |
| Do keys held from the launch bind reach the surface, and can repeats be told apart? | **Yes.** Rune exposes `Tx::key_repeat()`; repeats are ignored. dusk also ignores all keys for 160 ms after opening and ignores chords with Cmd/Ctrl/Alt/Super. | unit tests in `surfaces::tests`; live Super-modified key test. |
| Do Hyprland binds still work while the menu is open? | **Not conclusively tested.** The layer surface takes keyboard interactivity on demand; the documented recovery bind is `pkill -x dusk`, and the watchdog removes a hung menu. | README recovery bind; watchdog exits after 10 s without a poll. |
| Can Rune detect reduced motion on Linux? | **Yes.** `Cx::is_reduced_motion()` follows the host; a scene override verifies the reduced path. | `--scene reduced`; Rune's runtime settings. |
| How long from launch to first frame? | **~110 ms warm**, up to ~0.3–0.7 s on the first run after a rebuild (cold driver/shader caches). | `DUSK_TIMING=1` phase lines. |

## Decisions

- **D1 confirmed:** one-shot process. The menu exits after an action or a close.
- **D2 confirmed:** blur comes from the compositor. Every theme also reads without it.
- **D3 confirmed on one monitor:** one focused-monitor menu and a dim-only surface on every other
  display. The focused monitor comes from the compositor, falling back to the first display because
  winit's `primary` flag was false for the only monitor on this machine.
- **Rune gap:** keymap fd offset and layer focus events are carried in the fork branch pinned by
  `Cargo.toml`. `KeyPolicy::Exclusive` did not block this build: on-demand focus works once the
  keymap is read.
